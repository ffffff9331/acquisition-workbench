# 获客工作台资料索引

## Windows 桌面软件

本项目已经配置为 Windows 桌面软件，而不是只能在浏览器里打开的网页。界面与业务数据默认保存在当前电脑本地，不依赖 macOS 专属能力，也不需要在线服务器。

在 Windows 10 / Windows 11 上安装 Node.js 20 LTS 或更高版本后，在本项目目录打开 PowerShell，依次执行：

```powershell
npm install
npm run dev:desktop
```

第二条命令会自动寻找可用端口，再打开「获客工作台」桌面窗口，不会因为电脑上已有 Vite 服务而打开错误版本。需要生成可交付给客户安装的 Windows 安装程序时，执行：

```powershell
npm run dist:win
```

完成后，安装包会生成在 `release` 文件夹中。项目使用 NSIS 安装器，客户可选择安装目录，并会创建桌面和开始菜单快捷方式。

开发与打包脚本均使用 Node.js 跨平台命令；没有使用 AppleScript、macOS 路径或 Unix 专属复制命令。中文源文件采用 UTF-8 编码，适合 Windows 中文环境。

## 当前 Core

当前版本实现所有行业共用的客户增长 Core、联网选题发现、六种渠道基础能力、官方 AI 积分账户和第一份可安装的卫浴行业内容包。签名插件包下载和远程自动装配将在后续接入。

```text
工作台
获客
线索
意向客户
客户
复盘
```

“获客”先按渠道横向展示基础能力：

```text
抖音
小红书
微信
线下活动
转介绍合作
B站
```

客户先选择自己准备使用的渠道，再按需安装行业内容包。渠道与行业包相互独立：安装内容包不会自动启用渠道，未安装任何行业包时也可以正常使用空白渠道工作区。

当前卫浴行业内容包可以完整预览共享行业知识、客户问题、证明素材、表达边界和六渠道模板。安装后可逐渠道添加原生草稿；渠道任务、来源编号、线索关联和结果记录仍然使用同一套共享底座。

Core 已支持本地保存以下业务动作：

```text
新建线索
记录来源、需求、负责人和下一步
线索转为意向客户
意向客户标记成交并转为客户
客户回访提醒
按来源查看线索、意向和客户结果
```

渠道任务进入“已发布、执行中、跟进中或已完成”状态后，会拥有可在线索中选择的来源编号；结果会继续进入现有的意向客户、客户和来源复盘流程。

获客机会研究支持按全网、抖音、小红书、微信内容和 B 站检索公开网页，也可以打开对应平台搜索页后人工保存页面发现。生成前必须先填写主推产品、目标客户和希望客户执行的下一步动作；工作台还会记录服务范围、真实证明、差异和承诺边界。

工作台提供客户原话、比较决策、避坑投诉、案例结果和本地需求五类搜索方向。至少保存两条真实来源后，才允许形成获客机会。结果不再只有标题，而是包含目标客户、购买阶段、需求信号、内容价值、证明素材、承接动作、适合渠道和风险提示。人工确认后，可以把机会送入抖音、小红书、微信、B站或线下活动的执行区。

从 `0.17.0` 起，机会与送入渠道后的具体选题或任务 ID 建立正式关联。系统沿着渠道任务、发布 / 执行记录、来源编号和客户状态回传曝光、到场、平台咨询、登记线索、有效线索和成交。用户可以记录“继续投入、调整后再试、停止投入”，下一次形成机会时会把这些本地真实结果作为历史实验输入，而不会把少量结果外推成行业规律。

从 `0.18.0` 起，获客机会与渠道执行之间增加通用「内容生产台」。用户先建立所有渠道共用的内容简报，再按抖音、小红书、微信、B站、线下活动或转介绍合作建立独立渠道版本。每个版本分别保存标题、开头、结构、正文 / 脚本、客户下一步、封面文案、画面素材安排、事实核对项和历史快照。

内容草稿仍通过统一 AI 服务生成，但生成请求只使用用户选中的真实来源、内容简报和当前渠道规则。AI 覆盖已有草稿前会自动保留历史版本。最终版本必须完成来源证据、证明素材、事实核对、渠道表达、素材准备和人工通读检查后才能锁定；锁定后共用简报和引用来源同时冻结，避免最终稿失去原来的依据。发布仍由用户在平台内手工完成。

从 `0.19.0` 起，内容生产台增加三层「内容体检」：本地固定规则先检查正文、来源、证明方案、占位内容、绝对承诺、承接动作、素材安排和事实核对项，不调用模型也不消耗积分；用户再按需调用 AI 深度评审，检查客户相关性、内容价值、证据支撑、具体程度、渠道适配、转化清晰度和执行可行性；最后仍由人工处理问题并确认是否发布。AI 评分只用于辅助修改，不预测流量、咨询量或成交率。

每次评审都会绑定当前草稿指纹。标题、正文、承接动作、封面或素材安排变化后，旧评审会保留为历史参考，但「体检问题已处理」和「人工已通读」自动清空，必须重新评审或重新确认后才能锁定。这让工作台检查的是准备是否充分，而不是用一个看似精确的分数替代经营判断。

从 `0.20.0` 起，最新评审可以继续生成「候选优化稿」。AI 只针对评审问题修改内容，明确展示准备修改的部分和仍需人工补充的事实或素材，不会自动覆盖当前草稿。用户采用候选稿前会自动保存旧版本；采用后旧评审立即失效，必须对新稿重新评审和人工确认。

最终稿锁定并关联到具体渠道任务后，工作台可以根据该任务的真实曝光或到场、咨询、有效线索、成交结果和人工复盘结论生成学习建议。学习建议分为继续保留、下次调整、明确避免、下次生成规则和解释边界；只有用户主动采用的规则才会进入后续同渠道草稿和候选优化稿。结果或人工结论变化后，旧规则自动停止进入生成输入，避免把错误归因持续放大。

官方模式调用官方网关，成功后读取服务端返回的本次扣分和扣后余额；自有 API 模式由 Electron 主进程读取加密 API Key，调用客户配置的 OpenAI 兼容服务，不访问官方积分账户。搜索服务与 AI 服务相互独立，搜索 API Key 同样使用 Windows 系统安全存储。

## AI 服务

从 `0.4.0` 起，桌面版顶栏提供全局的「AI 服务」入口。它是所有未来获客能力共用的生成服务，不属于某一个短视频或小红书模块。

客户可以选择：

```text
官方 AI 服务
-> 使用工作台编号和服务授权码
-> 由工作台服务端统一处理模型、行业规则、余额与用量

接入自己的 AI 服务
-> 填写 OpenAI 兼容服务地址、模型名称和 API Key
-> 费用直接由客户向第三方服务商支付
```

API Key 和官方服务授权码不会写入浏览器本地数据、客户资料或数据导出文件。Windows 桌面版会通过 Electron 的系统安全存储进行加密保存。第三方服务支持基础连通性测试和结构化聊天补全调用；正式地址必须使用 HTTPS，仅 `localhost` 与 `127.0.0.1` 开发环境允许 HTTP。工作台只保证接入和工作流结构，不承诺第三方模型的输出质量、价格、限流或可用性。

官方 AI 服务使用积分账户。客户端从官方网关读取真实余额、冻结积分、动态充值套餐和最近明细；充值时只向官方网关创建订单，支付成功后必须由服务端收到支付回调并入账。一次生成成功后，官方网关返回本次扣除积分和扣后余额。模型供应商 API Key、支付商户密钥、积分兑换比例和计费规则都不进入客户电脑。

当前「形成获客机会」「生成渠道草稿」「AI 深度评审」「候选优化稿」和「结果学习建议」已经接入统一 AI 通道。官方积分生成与自有 API 生成共用同一工作流，并通过业务任务、真实来源、结构化输出、本地硬门槛、AI 语义评审、人工确认、具体渠道任务归因和真实结果回传减少无效生成；真实官方调用仍取决于你部署的官方网关、模型路由和服务端账务实现。

官方网关地址是公开配置，不属于秘密。正式发版前，在 `electron/official-service.json` 中填写 HTTPS 网关地址，或在开发环境设置 `ACQUISITION_WORKBENCH_OFFICIAL_API_URL`。默认配置为空，因此没有官方网关时客户端只显示“积分服务尚未开通”，不会展示虚假余额或充值套餐。
