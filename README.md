# 获客工作台

> 面向中小企业和门店的模块化客户增长工作台。

- **当前版本：** `v0.37.0`
- **项目状态：** 内部开发 / Windows 测试版
- **仓库权限：** Private，不对外公开

## 项目简介

获客工作台不是某个行业的一套固定表单，也不是自动登录平台、批量发布内容的营销机器人。

它由一个跨行业通用的客户增长 Core、多个渠道基础能力和可按需启用的行业规则包组成。交付时可以根据客户的行业、获客渠道和实际需求组合不同模块，不需要每次从零开发一套软件。

```text
通用 Core
  + 渠道基础能力
  + 行业规则包
  + 行业打法包
  = 客户专属获客工作台
```

首次交付时，安装人员先导入由服务方生成的方案授权包，再在「获客配置」中选择客户行业与近期准备执行的获客方式。系统会自动汇总并启用对应渠道、安装对应行业规则和打法包，并指定一个当前默认打法；没有选中的渠道和打法不会进入客户的日常工作区。对已有工作台重新应用配置时，系统只增加能力，不会删除既有渠道、历史打法、线索、客户或复盘记录。

产品重点不是“生成一篇内容就结束”，而是把真实来源、内容生产、人工执行、线索承接、成交结果和持续复盘连接成一条可追踪的工作流。

## 产品结构

### 通用 Core

所有行业共用六个一级工作区：

```text
工作台 / 获客 / 线索 / 意向客户 / 客户 / 复盘
```

Core 负责保存客户增长过程中的通用对象、状态和结果，包括：

- 获客任务与来源编号
- 线索登记、筛选和负责人
- 意向客户跟进与下一步任务
- 预约、关键沟通、方案、报价、成交和暂不推进的过程记录
- 成交、丢单和客户沉淀
- 回访、复购与转介绍提醒
- 渠道来源与业务结果复盘

### 渠道基础能力

渠道作为独立能力按需启用，当前包括：

- 抖音
- 小红书
- 微信
- B站
- 线下活动
- 转介绍合作

不同渠道共享客户、来源、线索和复盘底座，但分别保留适合平台的内容结构、素材要求、检查项和执行记录。

工作台不代替用户登录平台，不保存平台 Cookie，也不自动发布、自动私信或自动群发。最终发布和客户沟通由用户人工完成，以降低账号风险并保留经营判断。

### 行业规则包

行业规则包为联网研究和内容生产补充行业词典、搜索扩词、需求信号、来源筛选、机会评分、证据要求、制作约束、表达边界和渠道适配规则。

当前首批可测试规则包：

```text
家装家居 > 卫浴门店
家装家居 > 门窗门店
家装家居 > 定制柜门店（含阳台柜场景）
家装家居 > 装修公司
```

安装人员可先在「获客配置」选择客户行业，再把其中一个设为当前使用的行业规则。首次配置会自动带入所选打法需要的渠道；切换只影响之后的新研究与内容制作，不会创建演示草稿或改写历史机会和任务。规则包不包含固定标题和固定正文，具体选题、标题和正文必须由客户当前资料、真实联网来源、行业规则和所选渠道动态形成。

后续行业规则包可以独立制作、签名、下载和安装，不改变通用 Core。客户可以只启用自己需要的渠道与行业规则。

### 行业打法包

行业打法包把一个已选行业规则和一个已启用渠道组合成一条可执行的获客路径。它回答的是“在这个行业、这个渠道里，客户下一步具体怎么推进”，而不是给客户塞一套固定标题或通用话术。

当前用于验证框架的打法包：

```text
卫浴门店 + 抖音 = 卫浴短视频 · 到店/量尺预约
卫浴门店 + 小红书 = 卫浴装修案例 · 私信现场判断
卫浴门店 + 转介绍合作 = 卫浴老客服务体验 · 自愿转介绍
卫浴门店 + 转介绍合作 = 卫浴设计师合作 · 需求转介与方案协同
卫浴门店 + 线下活动 = 卫浴老房改造 · 社区现场判断
```

每份打法包会为之后的新研究、人工执行与线索承接提供目标客户、切入场景、主要承接动作、线索判断字段、跟进节奏和复盘指标。通过「获客配置」应用打法时，系统会自动启用它需要的渠道；它不会创建内容、私信客户或安排预约。历史机会和内容任务会保留当时使用的打法包编号，便于后续复盘。

老客户转介绍包把服务体验置于推荐之前：先记录回访和遗留问题，再由客户自愿介绍、且新客户本人同意沟通时进行人工交接。它不以推荐次数、晒图、群人数或联系方式数量当作成果，也不支持强制分享、诱导打卡、未经同意保存联系方式或自动发送触达内容。

设计师合作包把项目协同置于转介之前：先明确设计师、门店和业主各自能解决什么、谁负责什么、如何交接资料和反馈进展，再在业主本人同意后承接。它不支持索取或导入合作方客户名单、绕开既有沟通关系、擅自使用图纸与项目资料，或只按合作伙伴数量和拜访次数判断成果。

社区活动包把活动许可、具体社区场景、现场服务、最小必要登记、人工跟进和服务成本放入同一条链路。它不支持未经许可摆点或入户、导入住户名单、强制扫码加微信、以抽奖换联系方式，或只按人流、扫码和登记数量判断活动效果。

### 方案授权包

客户可以在工作台中预览全部已发布的方案方向，但未获得授权的方案不能进入配置步骤。服务方根据客户工作台显示的安装编号，生成并交付一个签名的 `.acqpack` 文件；导入时应用会校验：

- 方案是否属于当前版本已支持的方向
- 文件是否由服务方签名，且内容未被篡改
- 是否绑定当前工作台编号
- 是否已经到期

通过校验后，方案中声明的行业规则和打法才会出现在客户可选择的配置清单中。该机制用于正常商业交付、防止误装与普通复制；本地客户端不能提供绝对防破解保证，正式规模化销售仍应配合服务端授权、设备管理、更新签名与客户服务流程。

### 服务商方案发行台

服务商可在自己的电脑上运行本地「方案发行台」，从已发布的方案目录中选择一个方向，填写客户名称、客户工作台编号和可选有效期后，生成绑定该客户工作台的 `.acqpack` 文件。发行台会同时将授权包副本和发行记录保存在服务商本机的 `.licenses` 目录中，便于交付核对。

```powershell
npm run license:console
```

发行台只监听本机 `127.0.0.1`，签名私钥只从服务商项目的 `.keys` 目录读取，二者均不进入客户 Windows 安装包。台账中的「登记撤销」仅是服务方本地记录：已被客户离线保存的旧授权包不会因此即时失效。在线撤销、续费、设备管理和支付对账仍需后续接入真实服务端授权中心。

当客户从匹配渠道登记新咨询时，工作台会根据当前打法包显示对应的线索补充字段。字段随客户档案一起保存；关键信息未补全时仍保留为待判断，不把一次咨询直接当成有效预约。资料齐全后，工作台只给出“可人工推进”的建议，店员还需明确作出判断，并在回显客户资料与筛选依据的确认页中确认，才能转入意向客户。没有匹配渠道或打法包时，线索登记保持通用空白表单和原有的快捷流转。

## 当前能力

### 联网选题研究

- 按全网或指定平台检索公开网页
- 保存真实来源，而不是只使用内置标题库
- 从客户原话、比较决策、避坑投诉、案例结果和本地需求中发现机会
- 使用已启用的行业规则动态扩展搜索词，不使用内置选题库替代搜索
- 要求至少两条真实来源后再形成获客机会
- 保存目标客户、购买阶段、需求信号、证据、承接动作和风险提示
- 使用确定性行业规则检查机会准备度，但不预测流量、咨询或成交

### 内容生产

- 建立跨渠道共用的内容简报
- 为不同渠道生成独立内容版本
- 保存标题、开头、正文或脚本、客户下一步、封面文案和素材安排
- AI 覆盖草稿前自动保留历史版本
- 支持本地规则检查、AI 深度评审和人工通读
- 行业规则同步进入成稿、评审和修订，缺失证据只提示补充，不允许模型编造
- 生成候选优化稿，但不自动覆盖当前草稿
- 完成证据、素材和事实核对后才能锁定最终稿

### 执行与归因

- 将最终稿关联到具体渠道任务
- 为执行中的任务生成来源编号
- 回收曝光或到场、咨询、有效线索和成交结果
- 记录继续投入、调整后再试或停止投入
- 根据真实执行结果提出学习建议
- 只有人工采用的规则才会影响后续同渠道生成

### AI 服务

支持两种配置方式：

1. 官方 AI 服务：客户使用工作台编号和授权码，通过官方网关消费预付积分。
2. 自有 AI 服务：客户配置第三方 OpenAI 兼容地址、模型和 API Key，费用直接向第三方支付。

第三方 API Key 和官方授权码由 Electron 主进程调用系统安全存储保存，不写入客户业务数据或导出文件。默认官方网关地址为空，未部署服务时不会显示虚假余额、套餐或充值结果。

## 安全边界

本项目明确不提供以下能力：

- 自动登录第三方内容平台
- 保存或共享平台账号、密码和 Cookie
- 自动发布、批量私信或批量群发
- 未经授权抓取联系人或客户资料
- 绕过平台风控、验证码或访问限制
- 用 AI 评分承诺流量、咨询量或成交率

所有模型输出都应经过事实核对和人工确认。行业规则包不得包含预制成稿、无法证明的效果承诺、虚假案例或违规平台操作规则。
