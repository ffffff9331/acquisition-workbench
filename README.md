# 获客工作台

> 面向中小企业和门店的模块化客户增长工作台。

- **当前版本：** `v0.23.0`
- **项目状态：** 内部开发 / Windows 测试版
- **仓库权限：** Private，不对外公开

## 项目简介

获客工作台不是某个行业的一套固定表单，也不是自动登录平台、批量发布内容的营销机器人。

它由一个跨行业通用的客户增长 Core、多个渠道基础能力和可按需启用的行业规则包组成。交付时可以根据客户的行业、获客渠道和实际需求组合不同模块，不需要每次从零开发一套软件。

```text
通用 Core
  + 渠道基础能力
  + 行业规则包
  + 行业打法包
  = 客户专属获客工作台
```

产品重点不是“生成一篇内容就结束”，而是把真实来源、内容生产、人工执行、线索承接、成交结果和持续复盘连接成一条可追踪的工作流。

## 产品结构

### 通用 Core

所有行业共用六个一级工作区：

```text
工作台 / 获客 / 线索 / 意向客户 / 客户 / 复盘
```

Core 负责保存客户增长过程中的通用对象、状态和结果，包括：

- 获客任务与来源编号
- 线索登记、筛选和负责人
- 意向客户跟进与下一步任务
- 成交、丢单和客户沉淀
- 回访、复购与转介绍提醒
- 渠道来源与业务结果复盘

### 渠道基础能力

渠道作为独立能力按需启用，当前包括：

- 抖音
- 小红书
- 微信
- B站
- 线下活动
- 转介绍合作

不同渠道共享客户、来源、线索和复盘底座，但分别保留适合平台的内容结构、素材要求、检查项和执行记录。

工作台不代替用户登录平台，不保存平台 Cookie，也不自动发布、自动私信或自动群发。最终发布和客户沟通由用户人工完成，以降低账号风险并保留经营判断。

### 行业规则包

行业规则包为联网研究和内容生产补充行业词典、搜索扩词、需求信号、来源筛选、机会评分、证据要求、制作约束、表达边界和渠道适配规则。

当前首批可测试规则包：

```text
家装家居 > 卫浴门店
家装家居 > 门窗门店
家装家居 > 定制柜门店（含阳台柜场景）
家装家居 > 装修公司
```

四个规则包可以先预览，再把其中一个设为当前使用的行业规则。切换只影响之后的新研究与内容制作，不会自动启用渠道、创建演示草稿或改写历史机会和任务。规则包不包含固定标题和固定正文，具体选题、标题和正文必须由客户当前资料、真实联网来源、行业规则和所选渠道动态形成。

后续行业规则包可以独立制作、签名、下载和安装，不改变通用 Core。客户可以只启用自己需要的渠道与行业规则。

### 行业打法包

行业打法包把一个已选行业规则和一个已启用渠道组合成一条可执行的获客路径。它回答的是“在这个行业、这个渠道里，客户下一步具体怎么推进”，而不是给客户塞一套固定标题或通用话术。

当前用于验证框架的首个打法包：

```text
卫浴门店 + 抖音 = 卫浴短视频 · 到店/量尺预约
```

这份打法包会为之后的新研究与成稿提供目标客户、切入场景、主要承接动作、线索判断字段、跟进节奏和复盘指标。启用它之前，必须先设为当前行业规则并手动启用对应渠道；它不会自动启用渠道、创建内容、私信客户或安排预约。历史机会和内容任务会保留当时使用的打法包编号，便于后续复盘。

## 当前能力

### 联网选题研究

- 按全网或指定平台检索公开网页
- 保存真实来源，而不是只使用内置标题库
- 从客户原话、比较决策、避坑投诉、案例结果和本地需求中发现机会
- 使用已启用的行业规则动态扩展搜索词，不使用内置选题库替代搜索
- 要求至少两条真实来源后再形成获客机会
- 保存目标客户、购买阶段、需求信号、证据、承接动作和风险提示
- 使用确定性行业规则检查机会准备度，但不预测流量、咨询或成交

### 内容生产

- 建立跨渠道共用的内容简报
- 为不同渠道生成独立内容版本
- 保存标题、开头、正文或脚本、客户下一步、封面文案和素材安排
- AI 覆盖草稿前自动保留历史版本
- 支持本地规则检查、AI 深度评审和人工通读
- 行业规则同步进入成稿、评审和修订，缺失证据只提示补充，不允许模型编造
- 生成候选优化稿，但不自动覆盖当前草稿
- 完成证据、素材和事实核对后才能锁定最终稿

### 执行与归因

- 将最终稿关联到具体渠道任务
- 为执行中的任务生成来源编号
- 回收曝光或到场、咨询、有效线索和成交结果
- 记录继续投入、调整后再试或停止投入
- 根据真实执行结果提出学习建议
- 只有人工采用的规则才会影响后续同渠道生成

### AI 服务

支持两种配置方式：

1. 官方 AI 服务：客户使用工作台编号和授权码，通过官方网关消费预付积分。
2. 自有 AI 服务：客户配置第三方 OpenAI 兼容地址、模型和 API Key，费用直接向第三方支付。

第三方 API Key 和官方授权码由 Electron 主进程调用系统安全存储保存，不写入客户业务数据或导出文件。默认官方网关地址为空，未部署服务时不会显示虚假余额、套餐或充值结果。

## 技术栈

- Electron
- React
- TypeScript
- Vite
- electron-builder
- NSIS Windows 安装器

应用以 Windows 10 / Windows 11 x64 为主要交付环境。业务数据默认保存在客户本机，目前不依赖持续在线的业务服务器；联网搜索、AI 生成、积分和支付能力需要对应服务端支持。

## 本地开发

建议使用 Node.js 20 LTS 或更高版本。

```powershell
npm install
npm run dev:desktop
```

仅启动浏览器开发页面：

```powershell
npm run dev
```

## 验证与构建

运行 AI 服务契约测试：

```powershell
npm run test:ai-service
```

运行行业规则包完整性测试：

```powershell
npm run test:industry-packs
```

运行行业打法包完整性测试：

```powershell
npm run test:tactic-packs
```

运行 TypeScript 和生产构建：

```powershell
npm run build
```

生成 Windows x64 安装包：

```powershell
npm run dist:win
```

构建结果生成在本地 `release` 目录，该目录不提交到 Git。正式测试安装包通过 GitHub Releases 单独发布。

## 安全边界

本项目明确不提供以下能力：

- 自动登录第三方内容平台
- 保存或共享平台账号、密码和 Cookie
- 自动发布、批量私信或批量群发
- 未经授权抓取联系人或客户资料
- 绕过平台风控、验证码或访问限制
- 用 AI 评分承诺流量、咨询量或成交率

所有模型输出都应经过事实核对和人工确认。行业规则包不得包含预制成稿、无法证明的效果承诺、虚假案例或违规平台操作规则。
